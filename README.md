# Erdős 339 — Palomar project package

**Build verification pending.** This ZIP contains the supplied density proof
development, project configuration, metadata, licence, and submission account.
It is not a completed Palomar registration or a verified compilation report.

Read ERDOS_339.md for the four compared statements, definitions, proof architecture,
source references and audit limits. The results are attributed to the 2003 work
of Hegyvári–Hennecart–Plagne; no mathematical novelty is claimed.

## Project files

- Challenge.lean and Solution.lean: independent modules containing the supplied
  mathematical definitions, statements and proofs. Neither has proof placeholders.
- comparator.json: selects the four principal density theorems.
- formalization.yaml: English project metadata, provenance and known gaps.
- lean-toolchain, lakefile.toml, lake-manifest.json: pinned Lean/Mathlib environment.
- LICENSE: MIT licence for this package.

The Challenge retains supporting proof development to avoid introducing sorries.
It is larger than the preferred small statement-only interface, but below the
hard Challenge size limits. The permitted standard axioms are propext, Quot.sound,
and Classical.choice; actual theorem dependencies have not been audited.

## Build and check

Install elan and the toolchain specified in lean-toolchain, then run:

```bash
lake update
lake exe cache get
lake build Challenge Solution
```

The included manifest was assembled from the dependency manifest at the pinned
Mathlib revision rather than generated by Lake. Regenerate it with `lake update`,
check its pins, and commit the generated manifest. Compilation and Comparator
have not been run here. Resolve all build errors without weakening statements.
Then check comparator.json using Comparator with NanoDa as described by the
current Palomar requirements. Update metadata only when the checks substantiate it.

## Upload and submit

1. Confirm the author/maintainer display name and licence. The package currently
   uses Alexander (AItoBit), from the supplied conversation context.
2. Upload the contents of this folder to the root of a public GitHub repository.
   Do not commit `.lake` or compiled output. Commit the final verified sources
   and regenerated manifest.
3. Obtain the full commit SHA with `git rev-parse HEAD`.
4. Open https://submit.palomar-registry.org/ and enter:

| Field | Value |
| --- | --- |
| Repository | Your public `owner/repository` |
| Commit | Full 40-character SHA of the final commit |
| Comparator configuration | `comparator.json` |
| Project directory | Leave blank for repository root |
| Formalization metadata | Leave blank for the default `formalization.yaml` |
| Existing Palomar ID | Leave blank for a new registration |
| Relationship | Select your truthful authorship or approval basis |

Palomar accepts a public GitHub repository and pinned commit, not a direct ZIP
upload. This ZIP is the project to unpack and publish. No GitHub publication or
Palomar submission was performed by preparing the package.

Palomar's editorial criteria require credible research interest and source
alignment in addition to mechanical correctness. Eligibility has not been
established here. Review and authenticate through the site only after checking
that the public metadata accurately describes your work.
